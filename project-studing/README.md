# Wildhaven Bishkek

Сайт зоопарка на React и Vite с Firebase Authentication, Firestore и Firebase Analytics.

## Firebase setup

Проект использует Firebase-проект `wildhaven-bishkek`. Клиентская конфигурация находится в `src/firebase.js`; значения можно переопределить переменными окружения `VITE_FIREBASE_*`. Firebase API key является идентификатором клиентского приложения, а не секретом: безопасность обеспечивают Authentication и правила Firestore.

1. В Firebase Console создайте базу данных Firestore в production mode.
2. В **Authentication → Sign-in method** включите **Email/Password** и создайте отдельную учётную запись администратора.
3. Скопируйте UID этой учётной записи и в Firestore Console создайте документ `admins/{UID}` (например, `admins/abc123`). Документ может содержать `{ "role": "admin" }`. Создание и изменение документов admins разрешены только через доверенную консоль; клиент не может самостоятельно выдать себе роль.
4. Опубликуйте правила из файла `firestore.rules` в разделе **Firestore Database → Rules**.
5. Запустите приложение: `npm run dev`, затем откройте `/admin`. После входа нажмите **Импортировать стандартные данные**, чтобы записать начальные коллекции `animals`, `tours` и `reviews`.

Для локального просмотра админки без Firebase Authentication в режиме разработки (`npm run dev`) доступен тестовый вход: `admin@wildhaven.kg` / `admin123`. Это только демонстрационный доступ для просмотра стартовых данных: сохранение, удаление и импорт в Firestore выключены. Тестовый вход включён исключительно при `import.meta.env.DEV` и не работает в production-сборке; для настоящего управления контентом используйте Firebase-аккаунт с ролью администратора.

Страницы животных и туров читают коллекции `animals` и `tours` через Firestore `onSnapshot`, поэтому правки появляются в браузере без перезагрузки. При первой настройке администратор нажимает **Импортировать стандартные данные**: записи из `src/data/zooData.js` загружаются в Firestore. До загрузки, а также если коллекция пуста или недоступна, публичный каталог сразу показывает исходные карточки с предупреждением о неполадке подключения. В админ-панели доступны формы создания, редактирования и удаления животных и туров.

## Страницы сайта

Публичные страницы доступны по отдельным адресам через React Router: `/` (главная с описанием, преимуществами и быстрыми переходами), `/animals` (каталог), `/tours` (туры и форма бронирования) и `/about` (контакты, часы работы и гиды). Скрытая админ-панель доступна по прямому адресу `/admin`, не имеет ссылки в публичном меню и требует Firebase Authentication и документа роли `admins/{UID}`. Для production-хостинга настройте SPA rewrite этих адресов на `/index.html`.

## Бронирования и Telegram

Бронирование доступно после входа или регистрации через Firebase Authentication; постоянная сессия хранится Firebase Auth в браузере. Вызов Firebase Callable Function проверяет пользователя и актуальную цену тура, создаёт заявку в Firestore, отправляет её в Telegram-чат и только после подтверждения Telegram показывает электронную квитанцию. Токен и ID чата хранятся в Firebase Functions Secrets, а не во фронтенде.

Чтобы развернуть Telegram-отправку, установите Firebase CLI, авторизуйтесь и в каталоге проекта задайте секреты, полученные у администратора Telegram-бота:

Cloud Function настроена на Node.js 22.

```sh
firebase functions:secrets:set TELEGRAM_BOT_TOKEN
firebase functions:secrets:set TELEGRAM_CHAT_ID
npm --prefix functions install
firebase deploy --only functions,firestore:rules
```

Для Cloud Functions проекту Firebase может потребоваться план Blaze. Добавьте бота в нужный чат и убедитесь, что у него есть право отправлять сообщения. Клиентская регистрация Telegram webhook/бота в проект не включена; секреты и фактический chat ID задаются владельцем бота при развёртывании. Онлайн-оплата и QR-коды не предусмотрены.

Перед публикацией замените демонстрационные контактные данные и примеры состава команды в `src/pages/AboutPage.jsx` на подтверждённые данные зоопарка, а также опубликуйте обновлённые правила из `firestore.rules`.
